# Maths for LLMs — companion repository

Every derivation in the book reproduced as runnable code, every arithmetic box
regenerated by a script, and every code exercise shipped as a failing test you
make pass.

![ci](https://github.com/USER/maths-for-llms/actions/workflows/ci.yml/badge.svg)

*Maths for LLMs* is Book 3 of **Mathematics for Everything**, by Avishek Nag,
Associate Professor in the School of Electrical and Electronic Engineering,
University College Dublin.

## Why this repository exists

Three reasons, in order of how much they matter.

**You can check the book in ten minutes.** Every numbered equation has a cell
that evaluates it and asserts the result. Every figure in the print edition is
produced by a script in `figs/`, not drawn by hand. Every number in every
arithmetic box is computed by `arith/` and re-checked by CI on every commit, so
the printed figures and the code cannot drift apart. If you find a disagreement,
that is a bug and `ERRATA.md` says how to report it.

**The arithmetic is useful on its own.** `arith/model_d.py` will tell you a
model's parameter count, its attention FLOPs at a given context length, the
sequence length at which the quadratic term overtakes the projections, and
where a config's `intermediate_size` comes from. You do not need the book to
use it.

**Nothing here was generated by a language model that had not been checked.**
That claim is cheap to make and expensive to fake, which is why the CI badge
above is load-bearing.

## Layout

    arith/          the reference models, and every printed number
      model_d.py      dense 8B: Parts I and II arithmetic
      model_s.py      sparse mixture-of-experts: Part III arithmetic
      small_model.py  the 1B shape used by the Chapter 2 tying box
      kv_cache.py     the KV cache, decode intensity, and section 11.8's crossovers
      accelerators.py machine balance, in one file because it ages fastest
      quant_formats.py bits per weight, for every format Chapter 13 names
    exercises/      one directory per chapter
      chNN/solution.py   stubs you fill in
      chNN/test_*.py     the tests that judge them
      test_arithmetic.py the CI guard on every printed number
    figs/           figure generators, colour and print modes
      data/           committed measurements, and the scripts that regenerate them
    measure/        checkpoint measurements: the three figures that need a
                    trained model rather than arithmetic.  See measure/README.md
    notebooks/      one notebook per chapter

## Quick start

    pip install -r requirements.txt
    python arith/model_d.py                      # the full ledger
    python arith/model_d.py --section attention  # the Chapter 3 box
    python arith/model_d.py --ffn                # the Chapter 6 box: where 14336 comes from
    python arith/scaling_budget.py               # the Chapter 10 box: 20 tokens/param against 2149
    python arith/scaling_budget.py --fit         # how fragile a five-parameter scaling fit is
    python arith/kv_cache.py                     # the Chapter 11 box: 128 KiB/token, and what fits
    python arith/kv_cache.py --intensity         # why decode is bandwidth-bound and not FLOP-bound
    python arith/model_s.py --moe                # the Chapter 12 box: 37 B active, 1341 GB resident
    python arith/model_s.py --capacity           # expert capacity, and the k everyone drops
    python arith/model_d.py --finetune-memory    # the Chapter 13 box: 137 / 25 / 13 GB
    python arith/quant_formats.py                # what a 4-bit format actually costs
    python -m pytest exercises/test_arithmetic.py

## Doing the exercises

Code exercises are marked **[C]** in the book. Each one ships as a test that
fails on a fresh clone:

    python -m pytest exercises/ch01 -q     # 4 failed — that is correct

Fill in the matching function in `exercises/ch01/solution.py` until the test
passes. Worked solutions live on the `solutions` branch. Appendix C prints the
answer and the path, not the code, which is what keeps the appendix inside
fifteen pages.

## Figures

Figures are generated in two modes from one source:

    MFE_MODE=colour python figs/make_fig33.py    # fig33.pdf,       digital editions
    MFE_MODE=print  python figs/make_fig33.py    # fig33_print.pdf, paperback interior

The print interior is black ink. KDP charges $0.012 per page for black ink,
$0.0255 for standard colour and $0.065 for premium colour, which on a 270-page
book is the difference between a $12.55 paperback royalty and a negative one.
Every figure therefore carries its information redundantly, in line style,
marker shape, hatching and direct labelling, and colour is added on top rather
than instead. A figure that only reads in colour fails CI.

## A note on the reference models

Model D and Model S are defined by hyperparameters, never by name, so a second
edition edits one table and re-runs this code. Model D's ledger is exact. Model
S's expert arithmetic is exact and is what the book quotes; its attention block
uses a documented multi-head latent parameterisation rather than a transcription
of any released checkpoint, which is why the total comes to 670 B against the
671 B usually reported, a difference of 0.15 per cent. The note is in
`arith/model_s.py` and the tolerance is asserted rather than hidden.
